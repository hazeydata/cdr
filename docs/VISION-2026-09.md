## Thesis

Bottom-up, not top-down national AI.

Put small local AI agents ("terrys") in middle workers' hands so they design custom team tools from **schemas and patterns**. Sensitive data never leaves the organization. Reusable **solution recipes** connect across Canada so solutions compound organically through an append-only recipe network — not literal blockchain, but an auditable, federated index of what works.

CDR **complements** GC AI Platform, the Digital Transformation Centre (DTC), and SSC infrastructure. It does not replace them. It fills the whitespace they cannot reach: locally owned AI nodes that operate within institutional security boundaries, building tools from published schemas using Mode 2 (schema-only) patterns, indexed through a shared recipe network with auditable provenance.

## Landscape Position

### What exists

| Initiative | What it does | CDR's relationship |
|------------|-------------|--------------------|
| **SCIP** (Service & Digital) | Shared cloud infrastructure for GC | CDR nodes can run on SCIP infra; CDR adds the AI agent + recipe layer |
| **GC AI Platform** | Centralized AI services for departments | CDR complements — GC AI Platform serves cloud-ready workloads; CDR serves the security-boundary workloads that can't go to cloud |
| **Cohere (Command R+)** | Canadian-founded LLM provider | A possible model backend for a terry; CDR is model-agnostic |
| **TELUS / OpenText** | Enterprise AI consulting + document management | Enterprise sales motion; CDR is bottom-up grassroots |
| **DGX Spark / Faraday appliances** | NVIDIA on-prem AI hardware | Optional hosting hardware for a terry node; not the CDR brand |

### The stale claim we don't make

"Canada has no sovereign AI." — This is no longer true. The landscape is crowded. CDR does not claim to be the only sovereign AI play.

### CDR's actual whitespace

1. **Locally owned node network** — not a cloud service, not a vendor contract. Each org owns its terry.
2. **Mode 2 schema-only pattern** — build tools from structure without touching data. No other offering does this systematically.
3. **Recipe index** — solutions compound across organizations. Publish once, fork many.
4. **Auditable profiles** — compliance is built in, not bolted on. Every tool traces to a profile + recipe.

## DTC Fit

CDR aligns with the Digital Transformation Centre's mandate to accelerate digital capacity across the Government of Canada. A DTC-supported Phase 0 pilot at HICC demonstrates the Mode 2 pattern: a terry builds a GC-compliant org-chart tool from a published PeopleSoft HR schema without accessing Protected B data. The recipe is published to the index so any department with PeopleSoft HR can fork it. This creates a flywheel — schema publication has a consumer now — that scales without additional DTC investment per department. CDR asks DTC for 90 days of support for one pilot node, not a platform buildout.

- Recipe index grows organically — each node contributes back
- Cross-department recipe forks demonstrate the flywheel
- Compliance profiles validated against real departmental security reviews
- CDR-OS (the open-source terry runtime) scoped and prototyped

## What CDR Is Not

- **Not a replacement for SSC** — SSC provides infrastructure; CDR provides the AI agent layer on top.
- **Not a cloud AI service** — CDR runs locally. That's the point.
- **Not a hardware company** — DGX Spark and Faraday appliances are optional engines, not the CDR brand.
- **Not a competitor to GC AI Platform** — CDR handles the workloads that can't go to cloud. They're complementary.
- **Not accredited by any GC body** — Phase 0 is a concept and demo. No claims of SA&A, ITSG-33 certification, or endorsement.
